# 약물감시(Pharmacovigilance) 개요

작성일: 2026-09-25

## 1. 정의와 목적

약물감시(Pharmacovigilance, PV)는 의약품이 시판된 뒤에도 이상사례를 수집·평가·예방해서 안전성을 계속 확인하는 과학 분야이자 규제 활동이다. 허가 전 임상시험은 대상자가 수천 명 수준이라 드물거나 장기적인 부작용을 놓칠 수 있다. 약물감시는 이 공백을 실제 사용 데이터로 메운다.

## 2. 핵심 개념

| 용어 | 의미 |
| --- | --- |
| 이상사례 (AE, Adverse Event) | 의약품 사용 중 발생한 모든 바람직하지 않은 의료적 사건. 인과관계는 따지지 않는다. |
| 약물이상반응 (ADR, Adverse Drug Reaction) | 약과 인과관계를 배제할 수 없는 이상사례 |
| 중대한 이상사례 (SAE) | 사망, 생명 위협, 입원 또는 입원 연장, 영구적 장애, 선천성 기형, 기타 의학적으로 중요한 상황 |
| 예상하지 못한 이상사례 (Unexpected) | 허가사항(Label) 또는 IB(Investigator's Brochure)에 기재되지 않은 반응 |
| SUSAR | Suspected Unexpected Serious Adverse Reaction. 중대하고, 예상하지 못했고, 인과관계가 의심되는 반응 |
| ICSR | Individual Case Safety Report. 개별 이상사례 보고서 |

## 3. 주요 업무 흐름

1. **수집**: 자발적 보고, 문헌, 임상시험, 소셜미디어, 환자지원 프로그램 등
2. **사례 처리 (ICSR)**
    - 접수 → 유효성 확인(최소 4요소: 확인 가능한 보고자, 환자, 의심약물, 이상사례)
    - MedDRA 코딩 → 중대성·예측성·인과성 평가 → 서술문(Narrative) 작성
3. **규제기관 보고**: 중대하고 예상하지 못한 사례는 보통 15일 이내 신속 보고. 전자 보고 표준은 ICH E2B(R3)
4. **신호 탐지 (Signal Detection)**: 불균형 분석 지표 사용
    - PRR (Proportional Reporting Ratio)
    - ROR (Reporting Odds Ratio)
    - EBGM (Empirical Bayes Geometric Mean, MGPS)
    - IC (Information Component, BCPNN)
5. **정기 보고**: PSUR/PBRER(시판 후), DSUR(개발 중)
6. **위해성 관리**: RMP(EU·한국), REMS(미국)

### 불균형 분석 2×2 분할표

|  | 관심 이상사례 | 그 외 이상사례 |
| --- | --- | --- |
| 관심 약물 | a | b |
| 그 외 약물 | c | d |

- PRR = [a / (a+b)] / [c / (c+d)]
- ROR = (a/b) / (c/d) = ad / bc
- 일반적인 신호 기준 예: PRR ≥ 2, χ² ≥ 4, a ≥ 3 (Evans 기준)

## 4. 규제와 표준

| 구분 | 내용 |
| --- | --- |
| 국제 | ICH E2A~E2F 가이드라인, WHO-UMC VigiBase |
| 미국 | FDA FAERS, 21 CFR 314.80 |
| EU | EMA EudraVigilance, GVP(Good Pharmacovigilance Practices) Modules |
| 한국 | 식품의약품안전처, 한국의약품안전관리원(KIDS), KAERS 보고 시스템 |
| 이상사례 용어 | MedDRA (SOC > HLGT > HLT > PT > LLT 5단계 계층) |
| 약물 용어 | WHODrug |

## 5. 인과성 평가 방법

- **WHO-UMC 기준**: 확실함(Certain), 상당히 확실함(Probable/Likely), 가능함(Possible), 가능성 적음(Unlikely), 평가 곤란(Conditional/Unclassified), 평가 불가(Unassessable/Unclassifiable)
- **Naranjo 알고리즘**: 10개 문항 점수 합산. 9점 이상 확실함, 5~8점 상당히 확실함, 1~4점 가능함, 0점 이하 의심스러움

## 6. FDA FAERS 공개 데이터

FAERS(FDA Adverse Event Reporting System)는 FDA가 받은 시판 후 이상사례 보고를 분기마다 공개하는 데이터베이스다.

- 다운로드 페이지: https://fis.fda.gov/extensions/FPD-QDE-FAERS/FPD-QDE-FAERS.html
- 형식: 분기별 zip(ASCII `$` 구분 텍스트 또는 XML). 2012Q4 이전은 레거시 AERS 형식이다.
- 로컬 보관 위치: `data/faers/raw/faers_ascii_YYYYqN.zip`
- 다운로드 스크립트: `scripts/download_faers.sh` (재실행하면 새 분기만 추가로 받음)

### 파일 구성 (분기당 7개 테이블, `primaryid`로 연결)

| 파일 | 내용 | 주요 컬럼 | 2026Q2 행 수 |
| --- | --- | --- | --- |
| DEMO | 환자 인구통계, 보고 정보 | primaryid, caseid, caseversion, age, sex, wt, occp_cod, reporter_country | 422,459 |
| DRUG | 약물 정보 | drug_seq, role_cod(PS/SS/C/I), drugname, prod_ai, route, dose | 1,627,225 |
| REAC | 이상사례 (MedDRA PT) | pt, drug_rec_act | 1,394,751 |
| OUTC | 결과 | outc_cod (DE 사망, LT 생명위협, HO 입원, DS 장애, CA 선천성 기형, RI 개입 필요, OT 기타) | 303,705 |
| RPSR | 보고 출처 | rpsr_cod | 11,295 |
| THER | 투여 기간 | dsg_drug_seq, start_dt, end_dt, dur | 326,027 |
| INDI | 적응증 (MedDRA PT) | indi_drug_seq, indi_pt | 1,124,333 |

추가로 `Deleted/DELETEyyQn.txt`에 삭제된 caseid 목록이 있다.

### 분석 시 주의사항

- **중복 제거**: 같은 `caseid`에 여러 `caseversion`이 있으면 가장 최신 버전만 쓴다. 분기를 합칠 때 특히 중요하다.
- **삭제 목록 반영**: 모든 분기의 DELETE 파일에 있는 caseid를 제외한다.
- **약물명 표준화**: `drugname`은 자유 입력이라 철자와 상품명이 제각각이다. `prod_ai`를 쓰거나 RxNorm 등으로 매핑한다.
- **역할 코드**: 신호 분석은 보통 주의심약물(PS) 또는 PS+SS만 대상으로 한다.
- **자발적 보고의 한계**: 과소 보고, 보도 영향(stimulated reporting), 분모(노출 인구) 부재 때문에 발생률은 계산할 수 없다. 불균형은 신호일 뿐 인과관계의 증거가 아니다.

## 7. 현재 약물감시 현장의 문제의식

| # | 문제 | 근거 | 무엇이 개선되어야 하나 |
| --- | --- | --- | --- |
| 1 | **처리량 폭증.** 모든 케이스를 같은 비용으로 읽는다 | FAERS 2026Q2 한 분기 보고 422,459건(우리 웨어하우스 실측). 한국 KAERS 2025년 277,279건 | 케이스별로 필요한 처리 깊이를 다르게 배분 |
| 2 | **사람의 시간.** 읽기만 건당 수 분 | 신호 평가 중 ICSR 내러티브 검토 건당 약 5.56분 (Warner et al., Clin Pharmacol Ther 2026, PMID 42522449, 저자 스스로 예비 수치라고 밝힘) | 사람은 판단이 필요한 건에만 |
| 3 | **LLM 비용과 지연.** 예아니오 선별에도 프런티어 모델을 쓴다 | Nemotron 3 Super 건당 1,672 ms, 368.5 토큰 (팀 선행 실측) → 분기 40만 건이면 순차 186시간 | 대량 판단은 싸고 빠른 모델로, 숙고는 드물게 |
| 4 | **그럴듯한 과잉해석.** 근거와 숫자는 맞는데 결론이 틀린다 | 고정 규칙은 심은 과잉해석 16건 중 1건만 적발, LLM 판정 포함 시 16건 (팀 선행 실측) | 해석 한계를 규칙으로 명시하고 판정 단계를 둔다 |
| 5 | **분기 배치 감시의 지연** | 불균형 기준을 넘은 뒤에도 정기 보고 주기까지 평가가 시작되지 않는다 | 적재마다 누적 재계산하는 연속 감시 |
| 6 | **데이터 품질.** 버전, 삭제, 약물명 난립 | 원천 보고 → 고유 케이스, 약물명 원문 수십만 종 | FDA 권고 중복 제거, 성분 정규화 |
| 7 | **감사 가능성.** 모델 출력의 근거를 추적하기 어렵다 | 규제 제출물은 근거 추적이 필수 (ICH E2D, GVP VI) | 모든 주장에 근거 ID, 모든 숫자는 SQL |

## 8. FlyVigilante 컨셉

**공개 초파리 커넥텀(MaleCNS) + Jev(TypeSafe AI의 System-1 판단 모델) + NVIDIA Nemotron(System-2)과 Agent Skills**로 만든 약물감시 에이전트다.

핵심 아이디어는 초파리 뇌가 이미 풀어 둔 **자원 배분 문제**를 에이전트 라우팅에 옮기는 것이다.

| 초파리 뇌 | 원리 | FlyVigilante 층 | 구현 |
| --- | --- | --- | --- |
| 감각 뉴런 (ORN, GRN, JO, VPN) | 모달리티별 병렬 수용 | Sensory Intake | FAERS·문헌·임상시험·라벨·디지털 채널 수용 스킬 |
| 안테나엽 투사 뉴런 | 입력 정규화 | Feature Encoding | 중복 제거, 성분 정규화, ICH 4요소 규칙 게이트 |
| Lateral horn | 학습 없는 즉시 반사 | Reflex | Jev 한 번의 호출로 타입 판단 7개 |

| 하행 뉴런 | 좁은 출력 병목 | Action | 근거 붙은 메모만 사람 큐로 |

**경계.** 커넥텀은 설계 원리와 실시간 라우팅 시각화를 준다. 임상 판단의 근거는 FAERS, 라벨, 문헌이고, 판단은 Jev와 Nemotron과 사람이 한다.

상세 구조는 `docs/ARCHITECTURE.md`, 측정 결과는 대시보드의 벤치마크 화면과 `web/public/data/bench.json`에 있다.
